### React里面的性能问题
React 性能问题通常集中在 “不必要的渲染” 和 “渲染成本过高” 两类。
或者说是：核心在于避免不必要的组件更新，以及降低单次渲染的计算成本。
### 常见性能问题来源：
1. 频繁 re-render：每次 render 都是新对象 → 子组件必更新
父组件更新 → 子组件全部重新渲染
没有做 memo / shouldComponentUpdate
2. 函数重复创建：每次 render 都生成新函数
3. 大列表渲染：
1000+ DOM 节点
diff + render 成本高
4. 状态设计不合理：
state 粒度过粗
一个 state 影响整个组件树

### 常见优化React性能手段：
1. React.memo → 避免组件不必要更新（组件缓存（渲染优化））->是在 React 16.6 引入的（2018年发布）
`之前的类组件包括shouldComponentUpdate和PureComponent`
2. useMemo → 缓存计算结果（缓存一个计算结果（value值））
3. useCallback → 缓存函数引用
4. 状态拆分 → 减少影响范围
5. 用虚拟列表（react-window）
6. 懒加载（React.lazy）


当状态发生变化时，React 有时会过度重新渲染。自 React 早期以来，我们对这种情况的解决方案一直是手动记忆化。在我们当前的 API 中，这意味着使用 useMemo、useCallback 和 memo API 手动调整 React 在状态变化时重新渲染的程度。但是手动记忆化是一种妥协。它会使我们的代码变得混乱、很容易出错，并且需要额外的工作来保持更新。

React 的核心思想是开发人员将其 UI 定义为当前状态的函数。可以使用普通的 JavaScript 值，如数字、字符串、数组、对象，并使用标准的 JavaScript 语法，如 if/else、for 等，来描述组件逻辑。其思维模型是，当应用程序状态发生更改时，React 将重新渲染。我们认为，这种简单的思维模型和与 JavaScript 语义密切相关的原则是 React 编程模型中的重要原则。

问题在于，React 有时会过于 reactive：它可能会重新渲染太多次。例如，在 JavaScript 中，我们没有简单的方法来比较两个对象或数组是否相等（具有相同的键和值），因此在每次渲染时创建一个新对象或数组都可能会导致 React 执行更多的工作。这意味着开发人员必须显式地记忆化组件，以免对更改做出过度的反应。

我们的目标是通过 React Forget 确保 React 应用程序默认具有恰当的 reactive：只有在状态值 有意义 地更改时才重新渲染应用程序。从实现的角度来看，这意味着自动记忆化，但我们相信，reactive 框架是更好地理解 React 和 Forget 的一种方法。一种思考方式是，当对象标识发生更改时 React 会重新渲染。而使用 Forget，当语义值发生更改时，React 就会重新渲染——但不会产生深层比较的运行时成本。

### 为什么要用React Hook? 它解决了什么问题？
Hooks 让 React 从“面向组件复用”升级为“面向逻辑复用”。
##  Hooks 出现前的问题：
1. 逻辑复用困难
只能用 HOC（高阶组件）或 render props
代码嵌套严重（“组件地狱嵌套”）
2. class组件复杂
this 指向问题
生命周期分散逻辑->同一逻辑分散在多个生命周期
`componentDidMount()
componentDidUpdate()
componentWillUnmount()`
3. 组件难以拆分:一个组件中混合多个逻辑（请求 / 订阅 / 事件）

### Hooks 解决的问题:
1. （核心）逻辑复用更简单-> function useFetch() {}
2. （核心）逻辑按功能聚合->useEffect(() => {// 请求逻辑}, [])
3. 函数组件拥有状态能力-> const [count, setCount] = useState(0)
4. 避免 class 复杂性

### Vue里面的哪些特性让你印象深刻？
Vue 的优势在于强大的响应式系统 + 模板驱动开发 + 编译时优化，让开发效率和性能达到平衡。
1. Vue 的响应式是它最大的亮点：(👉 自动依赖收集 + 精准更新)
Vue2：Object.defineProperty
Vue3：Proxy
2. 模板编译（Template → Render）-><div>{{msg}}</div>(编译成 render 函数 → Virtual DOM)
3. 双向绑定（v-model）-> <input v-model="name" />(自动处理 input + state)
4. Composition API（Vue3）-> setup语法糖（是类似 React Hooks，但更“响应式友好”）
` setup() {
  const count = ref(0)
}`
5. 指令系统（Directive）-> v-if / v-for / v-show(模板能力强，开发效率高)
6. 内置性能优化 ->编译时优化

### 你可以讲一下你在AI开发工具上比如cursor有什么样的一些AI使用体验?
我在开发中使用过类似 Cursor 这样的 AI 编程工具，整体体验是从“写代码”转变为“设计问题prompt + 校验结果”：
- 代码生成能力
可以通过自然语言直接生成函数、组件甚至接口逻辑
比如前端中快速生成 React/Vue 组件骨架、hooks逻辑
- 上下文理解能力
Cursor 可以基于整个项目上下文补全代码
比传统的 GitHub Copilot 更偏“工程级理解”，而不是单行补全
- 代码重构 & Debug
可以直接让它帮你优化代码结构
- 局限性
生成代码不一定符合业务语义
对复杂状态管理（如 Vue3 响应式）理解有时不准确

总结：AI负责加速，核心逻辑必须自己掌控
### 对于OpenClaw，你自己有没有像对你的一个去了解它的一些设计的一些？或者说Open Claw 的设计理念是什么？
把大模型能力从“单点智能”变成“系统能力”，
本质上是在做“AI能力的工程化封装 + 工具调用框架”，它的设计理念可以从三个点理解：
1. Agent化（智能体）
把大模型从“问答工具”升级为“执行任务的Agent”
可以：调用API，操作文件，执行多步骤任务
👉 类似 Auto-GPT 思路
2. Tool Use（工具调用能力）
模型不只是生成文本，而是：调用函数，使用外部系统
👉 本质是：LLM + 工具链 = 可执行系统
3. Workflow（工作流编排）
支持多步骤任务拆解：Task → Subtask → Execution
